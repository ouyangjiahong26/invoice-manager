# ADR-0011: 证明材料类型与批量配对可用性修复

日期：2026-10-05　状态：已接受

## 背景

腾讯云批次暴露三个问题：

- 报销口径需要佐证文件：充值 1096.50 进腾讯云账户余额、实际只消费发票金额，支付记录与发票天然不平，需要附充值/消费流水作证明；此前这类文件只能冒充发票类型上传。
- 两张腾讯云发票识别失败：文件名超 80 字符被 `staging._safe_name` 截断丢掉 `.pdf` 后缀，识别按文件名后缀分流走了图片路径，PDF 字节被当作图片发给识别服务拒收（且文件头部本就有 5 个脏字节）。
- 提交受挫无反馈：组内含未识别类型文件或缺明细/类别时提交按钮仅灰化，hover title 之外没有任何提示，用户不知道缺什么；"两侧金额不一致"的黄色提示被误读为不可提交。

## 决策

- **新增附件类型"证明材料"（kind=support）**：流水、回单、账单截图等佐证文件。不参与金额合计、单号校验、自动配对与金额互证；识别提示词（detect 与按类型重识别）能判出该类型；批量配对页与条目侧边栏都可上传，未配对区给出"证明材料不参与自动配对，请加入对应组"的专属提示；导出 zip 按类型命名自动生效（票据标注只盖序号）。
- **识别按内容分流**：`detect/prefill/reread` 以 `%PDF-` 魔数（头部 1KB 内）判定走 PDF 路径，文件名后缀仅作辅助；`_safe_name` 超长截断时保留扩展名。
- **提交反馈**：组校验从布尔改为问题清单（含未识别类型文件、缺发票/支付/明细/类别/实付款），组卡片行内常驻红字提示；提交按钮不再用 disabled 拦截点击，点击即列出各组缺项并滚动定位到第一个问题组；"两侧金额不一致"措辞注明小额优惠/抹零差异可照常提交。

## 后果

- `Attachment.kind` 增加 support（迁移仅 AlterField choices，无 DDL）；单条侧边栏、批量提交、看板计数、导出命名、留痕全部按既有 kind 机制自动兼容。
- 证明材料的金额字段选填（如流水金额 1096.50），仅供展示与留痕，不进 check_item 的净额核对——支付合计与实付款不平的警告仍会出现，由证明材料向审核人解释，这是有意保留的提醒。
- 前端 `groupValid` 与后端 `batch_submit` 对未知类型文件的拒绝口径对齐，消除了"前端放行、后端 400 无解释"的缺口。
