# ADR-0016: 提交时选择未存档批次

日期：2026-10-30　状态：已接受

## 背景

ADR-0013 规定学生提交自动归入组最新批次，ADR-0014 规定自助组成员提交自动归入自己最新创建的批次。目标批次由服务端按创建时间推断，请求与页面都不能指定。最新批次一旦存档，即使组内还有未存档的旧批次，提交也会被拒绝。看板默认落在最新批次，批次下拉只按创建时间排序，已存档批次不会后移。

## 决策

- 提交目标批次由请求显式指定，缺省取可提交范围内最近创建的未存档批次。
- 普通组：组成员与管理员可选该组任意未存档批次。
- 自助组：非管理员只能选自己创建且未存档的批次。管理员可选该组任意未存档批次。
- 看板新建条目跟随当前查看的批次，侧边栏显示目标批次。批量提交页提供批次下拉，提交请求带上所选批次。
- 看板批次下拉按组分组，组内未存档批次在前、已存档批次在后，各自保持创建时间倒序。打开看板未指定批次时优先最近创建的未存档批次，全部已存档时仍落在最新批次供查看。
- 已存档批次不能作为提交目标。批次必须属于所选组，跨组批次按越权拒绝。
- `Batch.Meta.ordering` 保持不变。“最新批次”仍按创建时间定义，可提交范围、看板排序与缺省选择在视图层完成，避免影响导出、后台与既有最新批次语义。
- 本 ADR 修订 ADR-0013 的“学生提交自动归入本组最新批次”与 ADR-0014 的“成员提交的条目进入自己最新创建的批次”。批次归属组、组内唯一命名、批次创建人审批自己批次的规则继续有效。

## 后果

- 最新批次存档后，只要可提交范围内还有未存档批次，成员仍能继续提交。
- 自助组成员不能把条目提交到他人批次，批次创建人的审批边界不变。
- 看板默认不再落在已存档批次，只有全部批次已存档时才进入只读查看。
- 批量提交页多一次批次选择。页面选项与服务端校验共用同一套范围规则，避免可选范围与可提交范围不一致。
- 存档与删除批次的权限不变。自助组成员仍需管理员处理旧批次。
