# ADR-0013: 用组隔离账号与批次

日期：2026-10-24　状态：已接受

## 背景

系统原先服务单一群体。现在要同时服务多个群体，各群体各自报销、各自导出，同一个人（管理员）可同时属于多组。原模型只有全局批次，学生提交自动进全局最新批次，看板对全部登录用户共享。只给账号打标签回答不了“这个学生进哪个批”“谁能看哪批条目”。

## 决策

- 组使用 Django 自带的 `auth.Group`，不新建模型，也不使用其权限语义。组名即展示名，成员关系用 `user.groups`。
- `Batch.group` 必填。建批时选组。每组的最新批次即该组的当前报销批次，学生提交自动归入本组最新批次。属于多个组的用户在提交时显式选组。
- 数据可见范围：管理员看全部组。其他用户只看自己所属组的批次、条目与附件。条目付款人本人保留自己条目的查看权，但写操作要求付款人仍在组内。附件下发、条目侧边栏与看板批次下拉都走同一套判断。
- 删除 `/media/` 静态下发路由，附件只经 `file_serve` 鉴权下发，避免绕过组隔离。
- 账号与组在 Django 后台维护：组页面可直接选成员，用户页面也可勾选组。组页面只保留名称与成员，不显示权限。
- 历史数据迁移到默认组：现有批次与全部账号在迁移中归入该组。管理员之后按群体另建组并添加成员。
- 导出仍按批次。批次已归属组，因此导出天然按组隔离。
- 各群体的期望发票抬头与税号相同，继续用全局环境变量，不挂到组上。
- `import_batch` 新增 `--group`。系统只有一个组时可省略，多个组时必须指定。

## 后果

- 新建批次必须先有组。没有组的数据库无法建批，看板与批量提交页会引导管理员先去后台建组。
- 未分配组的非管理员看不到批次，也无法提交，页面给出提示。
- 看板批次下拉按组分组展示。多组用户的默认批次是全部可访问批次中的最新一批。
- 调组后原付款人仍可凭条目链接查看自己的历史条目，但看板只列当前所属组的批次，不提供跨组历史列表入口。
- 批次名在同一组内唯一，不同组可以重名。导出文件名带组名与批次名，避免跨组同名批次重名。
- 组与批量配对的“配对组”是不同概念，前者写入领域术语表并在用词上区分。
- 管理员目前不受组限制。以后若需要“各组管理员只看本组”，要在此决策上另加范围规则。
