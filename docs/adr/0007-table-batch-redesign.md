# ADR-0007: 表格化主视图与报销批次

日期：2026-10-08　状态：已接受

## 背景

- 管理员的实际工作单元是“报销批次”（每批独立编号、独立汇总表、独立 PDF，见各批次处理流程），习惯 Excel 式操作：排序、筛选、删除、调整顺序、修改数据。
- 卡片看板适合浏览，不适合批量整理：卡片无序号、无筛选、调整顺序无从谈起。审核要进 Django admin，改金额要开整页表单，操作路径碎。
- Item 无顺序字段，导出序号按提交时间自动生成。管理员在 Excel 手工流程里反复做的“同类别连续重编号”（插一行、后面全部重排）在系统里无法表达。
- 无批次概念，导出固定导全部 approved，无法按批出表。

## 决策

- 表格主视图替换卡片看板：所有人共用一张表（序号/明细/类别/金额/付款人/状态/附件），批次下拉切换，状态/类别/付款人/明细搜索筛选。学生仍只能编辑/删除自己的行，状态与付款人列对学生是纯文本。
- 报销批次（Batch）：管理员建批，条目必填归属（`PROTECT` 防误删批次连带删条目），学生提交自动归最新批。Excel/zip 导出按批出（文件名带批次名），导出仅含该批 approved。
- 条目持久化顺序（Item.position）：全局递增数轴，导出序号 = 该批 `approved` 条目按 `（category__order, category__id, position, id）` 排序后的连续 1..M。表格序号列与导出严格一致，待审/退回行不占号（显示为空）。staff 在表格内拖拽调序，限定类别内（保持“同类别连续”铁律）。行内改类别后条目自动落到目标类别末尾。调序不留痕（拖拽高频可逆，留痕会淹没真实变更）。
- 侧边栏承载一切：新建/编辑/附件/留痕/警告全部进侧边栏（点表格行滑出），整页表单 `item_form.html` 退役。条目侧边栏共享可见（附件与留痕所有人可看），编辑控件限本人/staff。`check_item` 警告在侧边栏打开时对单条计算（深色检测逐图解码，不适合整表每行跑）。`/items/batch/` 批量配对页（ADR-0006）原样保留。
- 权限分档：学生改自己条目的明细/类别/金额/附件。staff 额外可改审核状态、付款人 owner（AI 导入错配的修正通道）、删任意行、拖拽调序。
- AI 导入命令（`manage.py import_batch`）：纯 AI 识别建条、不读人工汇总 xlsx。扫描目录（顶层散文件等于执行者垫付，一级人名子目录按 `first_name` 匹配付款人），经 `vision.detect` 逐张识别，再由 `pairing.pair` 加 LLM 兜底配对，最后建 pending 条目。待确认组与未配对不建条目，逐条进报告。

## 取舍

- 表格全量渲染 + 内存筛选，不分页：单批条目量级是几十行，引入分页只会让序号与“全量序”脱节。
- 序号是派生显示、position 是存储事实：表格与导出共用同一排序键，避免两套顺序。行内改类别归尾而不是保持原 position，因为“同类别连续”优先于“全局位置稳定”。
- 拖拽调序仅 staff：顺序直接影响导出序号与报销单格式，属管理员职责。学生提交的新条目按提交顺序追加到全局末尾。
- owner 纳入留痕快照：付款人变更（尤其导入修正）是高风险操作，old 与 new 必须可追溯。调序不入留痕。
- 卡片看板与整页表单直接删除，不留兼容入口：生产仅 1 条测试条目，无迁移负担，保留双入口只会让操作路径继续碎下去。
- 导出文件名直接用批次名（仅剔除引号/换行防破坏响应头）：批次名是管理员自起的中文，再做转义/编码只会得到不可读文件名。

## 后果

- 迁移自建“历史条目”批次承接存量条目（position=1），用户可随时删除。
- `views.py` 的附件构造/解析抽到 `core/attachments.py`、LLM 配对与建议抽到 `core/suggest.py`，供视图与导入命令共用。`new_<kind>_<i>_<role>` 字段名协议与 `/items/prefill/` 契约不变。
- ADR-0001 的“看板展示”与“admin 审核”主路径移到表格行内（状态行内改、点行开侧边栏）。Django admin 保留为兜底（含批次管理与状态批量动作）。
- 侧边栏交互（预填识别、动态附件卡片、金额对账）从整页表单平移进 `board.html`。表格为纯内联 JS，无静态资源构建链。
- 导入命令真实数据验证默认 `--dry-run`，不自动产生 API 费用。配对结果以命令报告为准，不回读 xlsx 纠偏，错配由 staff 在表格/侧边栏修正（owner 可改通道即为此服务）。
