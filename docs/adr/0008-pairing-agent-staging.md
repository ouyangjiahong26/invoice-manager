# ADR-0008: 批量配对智能体、会话暂存与单边发票组放行

日期：2026-09-29　状态：已接受

## 背景

- ADR-0006 的批量配对上线后实测成功率不足：8 个文件的批次（文件已编号、发票上手写金额，属理想材料）只配成 1 对。
- 失败根因在流水线结构：每张文件只识别一次（`thinking: disabled`），LLM 兜底是单轮纯文本摘要（`group_suggest` 不看图）——识别阶段看错一个数字，兜底拿到的一样是错的，没有纠正机会。
- 配对证据没吃满：识别提示词不提取手写标注（编号、手写金额），文件名不参与配对，`invoice_no` 提取了但规则与 LLM 都没用。
- 分组确认页只在顶部上传卡片有文件预览，组/待确认/未配对三区只有文件名 chip，人工核对要来回滚动。
- 单边材料无出路：有发票、暂缺支付记录的批次被整体拒绝，学生只能等材料齐了再整批重来。

## 决策

- **配对智能体（多轮、服务端自研循环）**：规则配对后仍有未决记录（待确认 + 未配对的发票/支付）时，进入定向重读循环——每轮挑未决文件，带着"候选记录摘要 + 针对性提问"（手写标注、备注区、金额数字）重新调视觉识别，合并修正字段后重跑 `pairing.pair` 与 LLM 兜底；最多 3 轮，字段无改善或无未决即提前结束。**不做置信度评分**：AI 判断配对结果，人只做预览页最终确认。
- **配对会话（服务端暂存）**：批量页上传的文件存 `MEDIA_ROOT/tmp/batch/<session_id>/`（meta.json 记归属用户），后续识别、重读、提交均凭 `session_id + file_id` 引用，不再重复上传。清理规则：提交成功立即删；每次 stage 上传时顺手清扫超过 30 分钟的残留目录；不建后台任务。修订 ADR-0006 的"文件由前端持有、服务端不暂存"取舍——多轮智能体需要随机回看任意文件，无状态前提不再成立。
- **证据扩展**：`DETECT_PROMPT` 增提 `handwritten_notes`（图面手写文字）；文件名、手写标注、`invoice_no` 全部进入 LLM 配对摘要；确定性规则新增"同发票号码并组"（同号重复拍摄归同组）。
- **单边发票组放行**：配不上支付记录的发票仍生成组、可提交为条目（实付款 0.00，条目带缺支付警告）；审核不通过后学生从看板重新打开条目、经侧边栏补传支付记录即可，无需重建条目。修订 ADR-0006 的"未配对不生成条目、单边组拒绝提交"：**单边支付组仍拒绝**（支付无发票等于没有报销凭证），单边发票组放行。
- **AI 流程可视化**：批量页右侧新增步骤面板，展示处理流水（上传/逐张识别/规则配对/智能体各轮动作/结果）。实现取分轮请求而非 SSE：智能体每轮是独立端点，返回本轮结构化动作列表，前端逐轮调用、逐轮渲染——8 文件量级仅 2-4 轮，往返开销可忽略，且免流式协议、天然可恢复。
- **不引入外部 agent harness（否决 pi）**：pi 面向编码任务（shell/文件编辑工具面），配对智能体只需"看图、提字段、重跑规则"三个动作；引入意味着生产单机多一套 Node 运行时、常驻子进程与密钥传递面。循环在现有 `vision.py` 设施上一百余行纯 Python，确定性可预期、可单测。
- **分组预览内嵌文件预览**：组/待确认/未配对三区的成员 chip 改为缩略卡片——图片直接缩略、PDF 给图标加"预览"，点击统一进放大浮层（图片原图、PDF 内嵌 iframe，blob URL 复用前端持有的对象）。不引 pdf.js、不加构建链。

## 取舍

- **分轮端点而非一次请求**：进度可见性来自结构化轮次返回；每轮独立可重试，失败只重跑当轮。
- **重读上限每轮 6 张**：防止极端大批次单轮请求过大；轮次上限 3 防死循环，两者都由服务端执行。
- **暂存不做跨用户隔离加密**：目录名 uuid + meta.json 归属校验足够（登录内系统、文件本就同批可见于上传者）；30 分钟 TTL 换取零后台设施。
- **手写标注仅作证据不作规则**：手写内容噪声大，交给 LLM 权衡，不进确定性规则。

## 后果

- 新端点：`/items/batch/stage/`、`/items/batch/agent-round/` 替换原 multipart 直传的 `batch_detect`/`batch_pair`/`batch_submit` 契约（改为 `session_id + file_id` 引用）。
- ADR-0006 的"文件由前端持有""单边组拒绝提交"两条被本 ADR 修订；"规则唯一实现在 pairing.py""LLM 失败静默降级"等继续有效。
- 学生补传支付记录复用条目侧边栏的附件上传，无需新功能。
