# ADR-0012: 界面视觉采用 LDC 设计令牌与模板内联样式

日期：2026-10-22　状态：已接受

## 背景

看板、侧边栏、批量页、登录页此前各自累积了一套接近 GitHub 早期风格的配色：蓝色导航条、`#1f6feb` 主色、`#d0d7de` 描边、黄绿红三种硬编码状态底色。样式分散在 base.html 的 160 行内联块与 batch_form.html 的页面样式里，同一语义（警告、成功、危险）在不同页面用不同色值，改一处不影响另一处。

学生主要在手机与安卓微信里提交票据，管理员多在桌面端审核与导出。两种屏幕下都需要清晰的表格、表单与状态区分，但项目没有前端构建链，服务端渲染，也没有静态文件目录，样式此前全部内联在模板里。

参考了同类项目的做法：workbuddy-manager 的界面视觉对齐 linux-do/cdk（MIT），采用 shadcn/ui new-york 风格、中性 zinc 灰阶，亮色为主可切暗色。本次改造沿用同一套设计语言，保持两个项目观感一致。

## 决策

- 视觉令牌取自 linux-do/cdk 的 `globals.css`：中性 zinc 灰阶、`--radius` 10px、统计卡 20px 圆角、极淡描边、无语义阴影。色值写成十六进制而非 oklch，色调分层用预设变量而非 `color-mix`，以兼容安卓微信内置浏览器的旧版内核。
- 令牌与组件类集中在 `core/templates/core/_design.css`，由 `base.html` 用 `{% include %}` 嵌进 `<style>`，仍走服务端渲染与页面内联样式，不新增静态文件目录、不引入构建链，也不改变生产环境的 nginx 与 `collectstatic` 配置。
- 按页面需要拆出两个模板块：`extra_css` 供带 base 的页面追加页面级规则，`extra_js` 备用。页面级规则只允许用 `var(--...)` 令牌，不允许再写色值。
- 亮暗双主题通过 `html[data-theme]` 切换，首次绘制前由 base.html 头部脚本按系统偏好或 localStorage 决定，避免闪白。
- 交互结构保持原样：看板行内编辑、拖拽调序、侧边栏、审核弹窗、全屏预览仍由既有 JS 驱动，JS 依赖的 id 与 class（如 `.attach-card`、`.attach-preview`、`#panel-form`）作为样式契约保留。
- 移动端在 720px 以下隐藏顶部导航，改用底部浮动胶囊导航；表格改为卡片式，字段名由 `data-label` 提供。

## 后果

- 语义色只有一套：`--success`、`--warning`、`--danger`、`--info` 及其浅底，状态徽标、警告横幅、对账结论都从这套变量取值。新增颜色要先进 `_design.css`。
- 模板之间不再重复定义颜色，页面内样式只剩分区排布一类规则。设计系统的类名同时被 JS 用于生成 DOM，改名需要同时改模板、JS 与样式。
- 增加了全局 `[hidden] { display: none !important }`：新布局里多处容器改成 flex 或 grid，否则 `hidden` 属性会被布局声明盖过。
- 看板新增整批汇总统计卡，`board` 视图在筛选前统计条目数与金额合计，筛选只影响表格。
- `Batch.Meta.ordering` 增加 `-id` 兜底：创建时间完全相同时按时间倒序会并列，`first()` 可能取到旧批次。
- 设计系统每页内联约 1300 行 CSS，页面响应拿不到独立的缓存头，缓存在 HTML 层面，依赖浏览器的 HTML 缓存与压缩。要恢复 CSS 独立缓存，得引入 `collectstatic` 与 nginx 静态目录，本次不做。
